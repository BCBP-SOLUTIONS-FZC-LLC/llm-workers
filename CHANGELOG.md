# Changelog

All notable changes to this service are documented here. Format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/); versioning aligned with SemVer ([VERSIONING.md](./VERSIONING.md)).

This service has never been deployed to any environment, and no version is released: everything lives under `[Unreleased]`. This file tracks what is currently true and what is outstanding. Where each LLD rule stands is in [`docs/lld-traceability.md`](docs/lld-traceability.md).

## [Unreleased]

- **The Dockerfile is at the repository root** (it was `deploy/Dockerfile`); the Makefile, workflows, docs and skills point at it. The credential helper line is double-quoted, which clears hadolint's SC2016 that failed the `Build image (cache)` check on the PR.
- **Production-readiness pass** (LLD rev 0.11). Chart: `values-dev|staging|prod.yaml`, autoscaling off by default and refused without a scaler address, `alerts.enabled` (five alerts), optional `networkPolicy.egress` and `ingressFrom`, `automountServiceAccountToken: false`, env order, `make chart-check` (helm lint and render for the three environments, validated with kubeconform; part of `make ci` and of `validate-quality`). `docs/runbooks/`: sixteen runbooks and an index that says which alerts are not in the chart and why. Slot activities: fixed content-free errors and a tenant-id check; `RecursionError`, over-long fact values and over-long or non-scalar coherence values handled. CI (from the security review): the engine token reaches only the fetching steps and is not written to disk; the registry build cache is written only on push events; trivy and smoke builds get no token; release and summary checkouts do not persist credentials; a `real-engine` job. **Reviewed and not changed, for the owner:** (a) the NetworkPolicy still allows all egress until the platform names its service labels (PL-3); (b) a `revise_outline` signal's `ref` and `type` are not validated against a pattern, because dropping an entry changes the revision and the API's contract for those fields is not recorded; (c) the gate returns on an approve signal while the row still reads `awaiting_outline_approval` (the API writes the row first, so the row should already say `generating`; tightening it changes the signal-versus-row rule and needs the owner's call); (d) `GO_PRIVATE_TOKEN` should be a fine-grained token with read access to the engine repository only (its scope cannot be checked from here), and the `buildcache` package on GHCR must be private; (e) the Cosign verify step in `release.yml` expects a tag identity, so a `workflow_dispatch` from a branch signs with a branch identity.
- **Review fixes** (LLD rev 0.10): chart codec key (`codecKey.secretName`, `codecKey.keyId`; the chart refuses to render without a key id) and no PodDisruptionBudget on single-replica queues; `TenantSlots.acquire` answers after `ACQUIRE_POLL_SECONDS` inside the workflow; a section whose slot request fails is closed `failed`; `run_state` is retried for an hour (`READ_RETRY_WINDOW_SECONDS`) instead of three attempts; wrong-shaped model answers in facts and coherence are dropped or end as `SchemaViolation`; the gate pauses `GATE_RECHECK_SECONDS` once past its deadline; a refused step on an open row fails the run recorded; `ci.yml` has no `paths-ignore`; README and CLAUDE.md say rev 0.10. No patch markers (nothing is deployed). New tests: `workflow/test_review_fixes.py`, `unit/test_model_answer_shapes.py`, `unit/test_chart.py` (needs helm); the three slot tests were rewritten for the bounded acquire. `make ci`: 207 passed, 1 skipped.
- **The image now passes the CVE scan** (`make trivy`, exit 0). `Dockerfile`: the final stage upgrades OS packages (apt, libpam) and removes `pip`, whose vendored urllib3, msgpack and setuptools carried HIGH findings the service never uses. One finding stays, in `.trivyignore` with a reason and an expiry (2026-12-31): `aws-smithy-json` 0.62.3 (CVE-2026-18140) in the Cargo.lock inside the `temporalio` 1.37.0 wheel, the newest release; drop it when a release locks 0.62.7 or later. `make trivy` mounts the file into the trivy container. Not yet run on GitHub.
- **CI reads the private engine with `GO_PRIVATE_TOKEN`** (the secret the IAM repo uses) instead of the `ENGINE_READ_KEY` ssh deploy key: the workflows rewrite `ssh://git@github.com/` to https with a stored credential, and the Docker build takes the token as a BuildKit secret (`--mount=type=secret,id=gh_token`; `make docker-build` falls back to `gh auth token`). `pyproject.toml` and `uv.lock` are unchanged. Not yet run on GitHub.
- **`docs/tender-gaps.md`**: every Tender-related gap, open and closed, in plain language (no internal rule ids), with its status and the decision or assumption behind it, for sharing with Tender. Docs only; the LLD is unchanged (no revision bump).
- **The adapter now runs against the real engine 1.1.0** (`make real-engine-test`, `generation/real_engine/`, Docker, not in `make ci`): throwaway Postgres 18 (RLS as the non-superuser `rag_activity` login), an S3 emulator (floci) and Valkey, started and removed by the test; Tender is a stub. 12 tests: `begin_stage` and `run_state`, `fail_run` from `pending`, `outline_building` and `suspended` (run and artefact failed, one `GenerationFailed`, `suspended_at` cleared), the section text round trip through S3, `RunGone` for another artefact's or tenant's section, `ContentUnavailable` for an unreachable store and for tampered bytes (the activity ends as the fixed `Internal` error, no cause), the pack keys from a Tender stub, and a malformed pack. **Engine finding:** a Tender outage makes `load_pack` return the platform default profile with no error, so `outline` fails for good (`PackOutlineMissing`); see ADR-0003. Also: the section graph end to end (`workflow/test_section_graph_end_to_end.py`), the suspension deadline on the real clock (`workflow/test_suspend_deadline_real_clock.py`), and the Helm chart rendered and linted for dev, staging and prod values (the ScaledObject `scalerAddress` renders empty).

- **Engine 1.1.0 adopted** (`tag = "engine-v1.1.0"`, annotated tag `047d834`, peels to `b6b92e6`, locked `b6b92e67031fa0f0e39656923c0f73682aea0ba0`; workers LLD rev 0.8). ADR-0003 gaps 1 to 5 are closed: the adapter reads `DomainProfile.outline_skeletons` and `fact_keys`, calls `load_section_text` and builds the engine's exported `PromptChunk`, `EvidenceChunk` and `VerificationRequest` (the look-alike dataclasses and the `getattr` reads are gone); `fail_run` records a failure from `pending`, `outline_building` and `suspended`, so the 30-day suspension timeout ends `failed` and no longer `UnrecordedFailure`. `ContentUnavailable` (any read failure) is **retryable** and bounded by the attempt count. New `PackOutlineMissing` (non-retryable). `engine_api_v1.json` is byte-equal to the tag's. Gap 6 (metrics identity, 1.2.0) stays open: `enable_metrics=False` and the `ValueError` pin remain. `make metrics-lint` now drives all 20 built metrics, including `unrecorded_failures_total`, `reconcile_recovered_total` and `poison_breaker_total`.

- **Observability Standard applied and proved on real output** (workers LLD rev 0.7): `make metrics-lint` (also in `make ci`, `make test-ci` and `validate-test.yml`) starts a worker on a dev server, scrapes the ops endpoint and the Temporal runtime's endpoint and runs `fastapicommon-metricslint check` and `check --strict` over each. Changes it forced: the label `outcome` on `llm_workers_section_outcome_total` is now `result` (a dashboard on `outcome` must change); `workflow_history_events` is the counter `llm_workers_workflow_history_events_total`; `domain`, `service` and `environment` are set on the Temporal runtime's series (`global_tags`) from the same function `init_metrics` reads; `llm_workers_workflow_duration_seconds` has its own histogram buckets. The SDK's `temporal_*` families are a named exception (PL-12). Draft requests for two shared `llm_*` names: `docs/observability-registry-requests.md`. Generated platform inventory: `docs/platform-observability-inventory.md` (`make metrics-inventory`).

- IA-1 closed (IAM: no part in the worker-to-Temporal mTLS); workers LLD rev 0.6; `TEMPORAL_TLS_CA_PATH` mentions removed from the contract doc.

### Added

- **The generation and extraction deployment of the Worker Pool**, built from the LLD (`docs/lld/llm-lld-workers-service.md`, rev 0.4): `GenerationWorkflow` (outline, optional gate, stage 1, facts, stage 2, coherence, finish; signals `approve_outline`, `revise_outline`, `cancel`, `resume`; a reconcile loop on every wait; a run deadline; a poison-section breaker), `SectionWorkflow`, `ExtractionWorkflow` and the `TenantSlots` entity workflow (per-tenant fan-out by update-with-start, FIFO, lease reaper, continue-as-new when suggested).
- The 15 activities, the one-module engine adapter (`activities/engine_api.py`) behind an `EngineApi` port, content-free error translation, background heartbeats, and the LangGraph section graph with no checkpointer.
- Six work queues and their `-control` queues, the `task_queue_for` selector, one process polling both a work and a control queue, graceful shutdown.
- AES-256-GCM payload codec and `DefaultFailureConverterWithEncodedAttributes`; mTLS client certificate from mounted files.
- 20 of the 25 LLD metrics built as `llm_workers_*`: 11 activity-side on `platform-fastapicommon` (served at the ops server's `/metrics`), 9 workflow-side on Temporal's meter (sandbox: workflow code cannot import fastapicommon); an optional OpenTelemetry interceptor. 5 are not built (no truthful event, ADR-0006).
- The ops server (`observability/ops.py`): a FastAPI app with fastapicommon's health and metrics routers, served by one uvicorn task in the worker's event loop; `/ready` goes 503 at the start of a graceful drain and the server stops after it.
- Logs and traces through `platform-fastapicommon`; the stdlib `temporalio` loggers come out in the same format.
- Rules of the platform as architecture tests: logs, metrics and traces only through fastapicommon (two named exceptions), no database access, no events (`make arch`).
- Worker Deployment configuration, a patch-marker registry (empty: no workflow change has shipped) and a replay helper.
- Operator commands WO-1 and WO-2 (`operator/commands.py`).
- Test suite: unit, workflow (Temporal time-skipping), replay, security (canary), integration and the engine contract tests; coverage about 96%.
- `Dockerfile`, a Helm chart (`deploy/helm/llm-workers`), CI (`ci.yml` with `validate-test`, `validate-quality`, image build, Trivy, smoke, PR summary, push), `release.yml`, `vuln-scan.yml`, `changelog-check.yml`.
- Repository skeleton: `Makefile`, git hooks, `.github/` (CODEOWNERS, SECURITY, templates, scripts), `.claude/` automation, `CONTRIBUTING.md`, `VERSIONING.md`, `ARCHITECTURE.md`, `docker-compose.yml` (a Temporal dev server), `.env-example`.
- ADRs 0001 to 0006 and `docs/module-map.md`.

### Known gaps

- **The engine's own metrics are off inside a worker.** fastapicommon allows one metrics identity per process, and the engine's `llm_retrieval_generation_*` names are refused under `llm-workers`; `build_rag_engine` passes `enable_metrics=False` (ADR-0006).
- Two Prometheus endpoints (the ops server on 8080, the Temporal runtime on 9464) until the platform team decides how metrics are collected; the Helm chart scrapes both through a PodMonitor (off by default, `podMonitor.enabled`: needs the Prometheus Operator CRDs; named ports `ops` and `sdk-metrics`); the `prometheus.io/*` pod annotations are dropped.
- **The engine's metrics identity is open (ADR-0003 gap 6, engine 1.2.0, not merged):** the engine's own metrics are off in a worker. The pack keys `outline_skeletons` and `fact_keys` are an assumed Tender contract.
- Not built (LLD §20.4, `docs/lld-traceability.md`): the zombie sweep and the freeze pause (owed by the API service and slice 7), load shedding, per-section residency re-read, alert rules, SLOs, runbooks, the disaster-recovery drill, a real-Postgres integration suite, `GenerationWorkflow` continue-as-new, five of the 25 metrics (`runs_suspended`, `runs_awaiting_gate`, `tenants_waiting`, `load_shed_steps`, `cost_per_document`).
- The release and CI pipelines have never run on GitHub; the image has not been built in CI.
